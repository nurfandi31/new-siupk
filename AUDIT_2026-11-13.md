## 1. Ringkasan Eksekutif

SIUPK Next secara arsitektur jauh lebih matang daripada legacy: Laravel 13, Inertia 2 + Vue 3, 20 domain, double-entry journal, tenancy per-shard, dan 115 file test. Namun pengujian langsung menunjukkan **jalur kritis yang benar-benar dapat dieksploitasi**, bukan hanya risiko teoretis:

- API Desktop Sync membocorkan **seluruh snapshot tenant, termasuk NIK**, tanpa autentikasi di non-production dan **lintas tenant oleh user login mana pun** di production.
- Holding API **fail-open** di semua environment bila key kosong.
- Halaman Access mengizinkan **reset password user lain tanpa permission**.
- Quick login di environment non-production dapat dipakai **mengambil alih akun Superadmin tanpa password**.
- Endpoint mobile verify/approve/pay **tidak memeriksa permission**.
- Pembayaran angsuran dari web **tidak menulis `loan_payments`**, sehingga laporan keuangan salah.

## 3. Koreksi Audit Sebelumnya (Penting)

Audit 11 November memuat tiga temuan yang **tidak lolos verifikasi ulang**. Koreksi ini bukan formalitas: dua di antaranya mengubah prioritas perbaikan.

### 3.1 Path traversal `/storage/{path}` - **tidak dapat dieksploitasi saat ini**

**Klaim lama:** `GET /storage/site/....//....//....//....//.env` dapat membaca `.env` tanpa login (P0, CVSS 9,8).

**Hasil verifikasi runtime:**

| Request | Status | Keterangan |
|---|---|---|
| `GET /storage/....//....//....//....//.env` | **404** | framework route menang |
| `GET /storage/../../../../.env` | **404** | ditolak |
| `GET /storage/..%2f..%2f..%2f..%2f.env` | **404** | ditolak |
| `GET /storage/....\....\....\....\.env` | **404** | ditolak |
| `GET /storage/site/....//....//....//....//.env` | **404** | ditolak |
| `GET /storage/tenants/3/logo.png` | **200** | file sah, dilayani framework |
| `PUT /storage/...` tanpa signed URL | **403** | ditolak |

**Penyebab:** `config/filesystems.php` menyalakan `serve => true` pada disk `public`. Laravel mendaftarkan route `storage.public` (`Storage::disk('public')->serve()`) dan route itu **terdaftar lebih dulu** serta menang atas route aplikasi `routes/web.php` -> `StorageServeController`. Route framework:

- menolak `..` dan backslash,
- mengirim `Cache-Control: no-store`,
- mengirim `Content-Security-Policy: sandbox`.

`StorageServeController` yang sanitizers-nya lemah memang **dead code** pada konfigurasi sekarang. Namun:

- jika `serve` dimatikan (mis. konfigurasi produksi diubah), route aplikasi aktif dan traversal menjadi eksploitable;
- symlink `public/storage` juga menyajikan file tanpa header pengaman bila Apache/Nginx mengizinkannya langsung;
- route generik tetap memperbesar permukaan serangan.

**Status baru:** **P2 - latent/dead code**, bukan P0. Tetap perbaiki sanitizer dan/atau hapus route fallback. Jangan andalkan "tidak tereksploitasi" sebagai alasan menunda.

### 3.2 `orWhere` API mobile - **tidak lintas tenant**

**Klaim lama:** `where('row_id',$id)->orWhere('id',$id)` menghasilkan `tenant_id=X AND row_id=? OR id=?`, sehingga user tenant A dapat membaca pinjaman tenant B.

**Hasil verifikasi:**

```
SQL: select * from `loans` where (`row_id` = ? or `id` = ?) and `loans`.`tenant_id` = ?
Bindings: [999999, 1, 1]
Result: null
```

Eloquent membungkus wheres yang sudah ada dalam grup ketika global scope diterapkan (`Builder::callScope()` -> `addNewWheresWithinGroup()`), sehingga tenant scope tetap mengikat kedua cabang. Uji live juga konsisten:

- `GET /api/v1/mobile/collection/loans/1` (loan demo, tenant 3) sebagai user tenant 1 -> **404**;
- `GET /api/v1/mobile/collection/loans/27` (loan local, tenant 1) -> **200**;
- header `X-Tenant-Code: demo` -> **403**.

**Status baru:** **bukan IDOR lintas tenant.** Namun kode tetap rapuh dan sulit dibaca; grouping eksplisit tetap disarankan. Masalah mobile yang **nyata** adalah tidak adanya permission check (bagian 5.5).

### 3.3 "Last admin" lintas tenant - **false positive**

**Klaim lama:** hitungan admin terakhir tidak dibatasi tenant.

**Verifikasi:** `UserRole` extends `TenantModel` -> `BelongsToTenant` -> `TenantScope` menambahkan `where tenant_id = ...` pada setiap query. Hitungan `UserRole::query()->where('role_row_id', ...)` otomatis tenant-scoped.

**Status baru:** **tidak terbukti.** Dihapus dari daftar temuan.

### 3.4 Klarifikasi lain

- `TenantSnapshotService::TABLES_IN_ORDER` **tidak** memuat `users` (tabel platform). Yang terekspos adalah `roles`, `user_roles`, `people`, `members`, pinjaman, dan jurnal tenant.
- `GET /access/users` tidak mengirim nomor telepon; yang membocorkan nama/email/telepon adalah halaman quick login `/user` dan `/login/user`.
- `VerifyDesktopApiToken` tidak sekadar "fail-open di non-production"; ia juga **meloloskan setiap user yang sudah login** di production (lihat 4.1).

## 4. Temuan KRITIS (P0)

### P0-1 - Desktop Sync: snapshot PII tanpa autentikasi (non-production) + lintas tenant + push terbuka

**Lokasi:** `app/Http/Middleware/VerifyDesktopApiToken.php:23-48`, `app/Http/Controllers/Api/Desktop/DesktopSyncController.php:29-50, 194-222`, `app/Domain/Sync/Services/TenantSnapshotService.php:21-67`, `app/Domain/Sync/Services/DesktopPushApplyService.php:22-69`

Tiga cacat bertumpuk:

1. Bila `DESKTOP_SYNC_API_KEY` kosong (default; tidak ada di `.env`/`.env.example`), request **tanpa autentikasi** lolos di non-production. Di production, middleware menolak (401) - ini satu-satunya kabar baik.
2. Bila key terisi, **setiap user yang sudah login** lolos - tanpa role, tanpa membership tenant. Ini berlaku juga di production.
3. `resolveTenant()` menerima `?tenant=`, `?tenant_id=`, atau `X-Tenant-Code` dan **tidak memverifikasi membership**. `TenantResolver` tidak dipakai untuk otorisasi di sini.

**Bukti live:**

| Request | Hasil |
|---|---|
| `GET /api/v1/desktop/sync/snapshot?tenant=local` (tanpa auth) | **200**, 284.964 byte, 45 tabel / 760 record |
| `GET /api/v1/desktop/sync/snapshot?tenant=demo` (tanpa auth) | **200**, 273.457 byte, 723 record |
| `GET /api/v1/desktop/sync/snapshot?tenant=demo` (cookie user tenant 1) | **200**, 15 `people`, NIK pertama `3201015001850001` |
| `POST /api/v1/desktop/sync/tenants/local/push` (tanpa auth) | **200**, `{"status":"success","rejected":[...]}` |
| `GET /api/v1/desktop/sync/snapshot?tenant=tidak-ada` | 404 |

Snapshot memuat `people.national_identity_number` (NIK), `members`, `loans`, `loan_installments`, `journal_entries`, `journal_lines`, `accounts`, `user_roles`, `documents`, dan `tenant_settings`.

**Dampak:**

- Kebocoran PII seluruh anggota (NIK, alamat, telepon) dan data finansial.
- User tenant A dapat menarik data tenant B.
- Endpoint `push` menerima mutasi untuk tabel yang diizinkan (`people`, `members`, `loans`, `journal_entries`, `user_roles`, dst.) tanpa autentikasi di non-production, atau oleh user login mana pun di production; ini dapat merusak/menyisipkan data dan memberikan role.
- `TABLES_IN_ORDER` **tidak** memuat tabel savings, `loans_received`, catatan supervisor, atau konten website - snapshot juga tidak lengkap secara fungsional.

**Perbaikan:**

- Wajibkan `DESKTOP_SYNC_API_KEY` di semua environment; tolak (503) bila kosong.
- Hapus fallback "user login"; jika memakai session, tetap wajibkan role/permission khusus dan membership tenant.
- Resolusi tenant hanya lewat `TenantResolver::resolveById($id, $user)` atau token yang **diikat ke satu tenant**.
- Untuk `push`, tolak `roles`/`user_roles` atau wajibkan `users.manage` + audit log; validasi schema per kolom; batasi rate.
- Tambahkan test: request tanpa key -> 401/503; user tenant A -> tenant B -> 403.

### P0-2 - Holding API fail-open total bila API key kosong

**Lokasi:** `app/Http/Middleware/VerifyHoldingApiToken.php:24-27`, `config/services.php:16-19`

```php
$configuredKey = (string) config('services.holding.api_key', '');
if ($configuredKey === '') {
    return $next($request);   // lolos di semua environment, termasuk production
}
```

`HOLDING_API_KEY` **tidak ada** di `.env` maupun `.env.example` -> default kosong.

**Bukti live (tanpa key):**

| Endpoint | Status |
|---|---|
| `GET /api/v1/holding/tenants/local` | **200** |
| `GET /api/v1/holding/reports/balance-sheet?tenant=local` | **200** |
| `GET /api/v1/holding/reports/consolidated/calk` | **200** |
| `GET /api/v1/holding/tenants` | **200** (526 byte) |

Legacy SIUPK justru **fail-closed** (`app/Http/Middleware/HoldingLicense.php`): token/slug kosong -> 401, lisensi tidak valid -> 401, kedaluwarsa -> 403. Ini regresi dari legacy.

Selain itu, key dapat dikirim lewat **query string** (`?api_key=`/`?holding_key=`), sehingga bocor ke access log, Referer, dan riwayat browser. Gunakan header saja.

**Perbaikan:** tolak 503 bila key kosong; wajibkan key di semua environment; tambahkan ke `.env.example`; rotasi key; audit log akses.

### P0-3 - Halaman Access: reset password & hapus user tanpa permission

**Lokasi:** `routes/web.php` grup `/access` (hanya `auth`, `tenant`, `subscription.active`), `app/Http/Controllers/Access/TenantUserManagementController.php`

`index()`, `create()`, `edit()`, `resetPassword()`, dan `destroy()` **tidak** memanggil `PermissionChecker::denyUnless()`. Hanya `store()`/`update()` yang dilindungi FormRequest (`users.manage`).

**Bukti live:**

- Sebagai user tanpa role (dev), `GET /access/users`, `GET /access/roles`, `GET /settings` -> **200**.
- Setelah sementara diberi role `viewer`:
  - `POST /access/users` -> **403** (FormRequest bekerja);
  - `POST /access/roles` -> **403**;
  - `POST /access/users/{id}/reset-password` dengan payload valid-shape -> **422** (validasi berjalan, **tidak ada 403**) - artinya otorisasi tidak pernah diperiksa.
- `DELETE /access/users/{id}` secara kode juga tidak memeriksa permission (hanya `assertBelongs()` cek tenant).

**Dampak:** user dengan role terbatas (mis. `viewer`) dapat:

- mengganti password admin/owner satu tenant -> **account takeover**;
- menghapus user lain (kecuali admin terakhir);
- membaca daftar user, role, dan konfigurasi.

Diperparah oleh `PermissionChecker` fail-open untuk user tanpa role (P1-6): user baru tanpa role otomatis punya akses penuh.

**Perbaikan:** middleware `permission:users.view` / `users.manage` dan `roles.view` / `roles.manage`; `denyUnless()` di setiap method; test permission matrix untuk `viewer`, `kasir`, `admin`, dan user tanpa role.

### P0-4 - Quick login passwordless: takeover Superadmin

**Lokasi:** `config/quick_login.php`, `routes/web.php:183-196`, `app/Http/Controllers/Auth/UserLoginController.php`

Default:


`.env` saat ini `APP_ENV=local` -> aktif.

**Bukti live:**

| Request | Hasil |
|---|---|
| `GET /user` (tanpa auth) | 200, daftar user platform + email/telepon |
| `GET /login/user` | 200, daftar user tenant + email/telepon |

### P0-5 - API Mobile: verify/approve/reject/pay tanpa permission

**Perbaikan:** tambahkan permission check per aksi; validasi `member_id` dan `cash_account_row_id` berada di tenant yang sama; audit log; batasi akses berdasarkan desa.

### P0-8 - Webhook Duitku & Xendit selalu 419 (CSRF)

**Lokasi:** `routes/web.php`, `bootstrap/app.php:47-50`

CSRF exempt hanya:

```php
$middleware->validateCsrfTokens(except: [
    'tripay/callback',
    'api/billing/tripay/callback',
]);
```

`/duitku/callback` dan `/xendit/callback` berada di grup `web` (CSRF aktif). Request server-to-server tidak membawa token -> **419**.

**Bukti live:** `POST /duitku/callback` -> 419; `POST /xendit/callback` -> 419; `POST /tripay/callback` -> tidak 419 (diproses controller).

**Dampak:** status invoice tidak pernah berubah menjadi paid; langganan tidak aktif; retry gateway terus gagal.

**Perbaikan:** tambahkan kedua path ke `except`, atau pindahkan ke `routes/api.php` dan andalkan signature. Catatan: `InvoicePaymentService` menyimpan referensi Duitku/Xendit di kolom bernama `tripay_reference` (nama kolom generik yang membingungkan, tetapi konsisten) - pastikan callback memakai nilai `merchant_ref`/reference yang benar.

### P1-11 - Export CSV master data 500: tenant context hilang sebelum stream

**Lokasi:** `app/Domain/Membership/Services/MasterDataCsvService.php:34-52, 140-158, 238-256`, `app/Support/Csv.php:17-36`, `app/Tenancy/Middleware/ResolveTenant.php:74-79`

**Bukti live:** `GET /master-data/members/export` (user login) -> **500** `RuntimeException: Tenant context has not been initialized` (Ignition trace ~896 KB).

**Penyebab:** `exportMembers()` membangun `Member::query()->...->lazyById()` (LazyCollection) lalu menyerahkannya ke `response()->streamDownload()`. **Dampak:** export anggota/kelompok/lembaga lain rusak; operator tidak bisa mengunduh data.

**Perbaikan:** materialisasi query sebelum return (`->get()`/cursor dengan context yang di-inject), atau bungkus callback dengan `TenantWorkbench::run()`, atau gunakan `response()->stream()` yang membangun query di dalam context.

### P1-12 - Tidak ada rate limit login + oracle enumerasi user

**Lokasi:** `routes/web.php` login, `app/Http/Controllers/Api/Mobile/MobileAuthController.php`

**Bukti live:**

- 8 login mobile password salah -> 401 semua, **tidak ada 429**.
- Login web juga tanpa throttle.
- Timing: user ada ~694 ms, user tidak ada ~370 ms (bcrypt hanya dijalankan untuk user yang ada).

**Dampak:** brute force password; enumerasi akun; OTP spam (3/jam per nomor tetap bisa dikirim ke banyak nomor).

**Perbaikan:** `RateLimiter` per IP+identifier (mis. 5/menit, 20/jam); constant-time dummy hash untuk user tidak ada; CAPTCHA setelah beberapa gagal; log percobaan.

### P1-13 - Stored XSS pada konten website publik

**Lokasi:** `resources/js/Pages/PublicSite/StaticPage.vue:41`, `PublicSite/BlogPost.vue:61` (`v-html`), `Website/SiteContentRequest` (konten `string|max:200000`), `WebsitePageController`

**Dampak:** user dengan `website.manage` - atau user tanpa role yang otomatis punya akses penuh - dapat menanam `<script>` yang berjalan di domain publik tenant, mencuri data pengunjung atau melakukan phishing.

**Perbaikan:** sanitasi HTML di server (allowlist tag/atribut) sebelum simpan; atau render sebagai markdown yang di-escape; tambahkan CSP.

### P1-14 - CSV formula injection

**Lokasi:** `app/Support/Csv.php:17-36`

`fputcsv` tidak menetralkan nilai yang diawali `=`, `+`, `-`, `@`. Nama anggota, alamat, atau nama kelompok dapat berisi formula; saat file dibuka di Excel, formula dieksekusi.

**Perbaikan:** prefix `'` untuk nilai yang diawali karakter formula, atau gunakan writer yang meng-escape.

### P1-15 - `.env.example` tidak memuat key keamanan

**Lokasi:** `.env.example`

## 14. Kesimpulan

SIUPK Next sudah menang jauh dari legacy pada arsitektur, keterbacaan, tenancy, dan cakupan laporan. Tetapi kematangan keamanan dan integritas datanya belum mengikuti: snapshot PII lintas tenant dapat diambil tanpa login (non-production) atau oleh user login mana pun (production), API holding terbuka, reset password tidak diotorisasi, quick login dapat mengambil alih Superadmin, dan laporan keuangan tidak menerima pembayaran dari aplikasi web.

Yang penting: **tiga temuan lama tidak terbukti** dan sudah dikoreksi. Audit ini memisahkan mana yang benar-benar dapat dieksploitasi dari mana yang hanya risiko laten. Prioritas perbaikan harus mengikuti bukti runtime, bukan asumsi.

Semua temuan di atas dapat diperbaiki tanpa menulis ulang arsitektur. **Sprint 0 (2 hari) menghilangkan seluruh jalur kritis yang dapat dieksploitasi dari internet.** Setelah itu, integritas `loan_payments` adalah prioritas tertinggi karena menyangkut angka yang dilaporkan ke OJK dan anggota.
